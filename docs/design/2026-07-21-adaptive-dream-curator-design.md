# 自适应做梦与两层 Curator 设计

## 1. 背景

DREAM 从银行聊天 Agent 的已完成会话中提炼两类长期产物：用户级 `USER.md` 人物画像，以及 Agent 级 AI 决策卡和 `DECISION_RULES.md`。现有闭环能够导入会话、调用语义模型、写入产物、创建快照并管理发布版本，但一次包含五段会话的做梦会串行调用多次外部模型。后期 Curator 或回写失败还会使前面已经成功的 Review 全部重做，导致耗时长、失败成本高。

本设计将外部模型限制在真正需要语义理解的步骤中；去重、证据合并、归档、格式化、快照、版本、报告和回滚全部由本地确定性代码完成。触发策略同时适配低频用户、高频用户和持续在线的多用户企业 Agent。

## 2. 设计目标

1. 完整会话写入事件账本时不调用大模型，通常在 10 秒内完成，1～2 分钟为宽松上限。
2. 一个批次的正常路径只调用一次 Agnes，完成用户事实和 AI 决策经验的联合语义提炼；结构非法时最多增加一次修复请求。
3. 普通做梦在 5 分钟内成功，或在达到截止时间后安全失败并恢复，不无限等待。
4. 确定性 User Curator 和 AI Curator 不依赖外部模型。
5. 可选的大模型语义合并默认关闭，失败时不影响普通做梦和当前 active 版本。
6. 用户画像严格按 `tenant_id + agent_id + user_id` 隔离；AI 决策卡在同一 Agent 内共享，但不得包含用户私人事实。
7. 保留可检查的 Markdown、JSON 和 JSONL 产物，以及快照、报告、版本和回滚能力。

## 3. 非目标

- 不修改短期记忆系统的 Redis 或 Headroom 逻辑。
- 不让 Agnes 直接写文件、切换版本或决定是否激活候选。
- 不把多个用户的原始会话混入同一个用户画像批次。
- 不保证外部免费模型始终在 5 分钟内成功；DREAM 只保证在截止时间内成功或安全失败。
- 不在本阶段建设生产银行 Agent 的初始画像管理系统。

## 4. 总体流程

```text
已完成会话
    ↓
FastAPI 校验并立即写入事件账本
    ↓
按用户维护 pending 队列、等待时间和输入规模
    ↓
满足自适应触发条件
    ↓
一次 Agnes 批量语义提炼
    ├── 用户事实提议
    └── AI 决策经验提议
    ↓
本地严格校验并由 Manager 应用
    ↓
确定性 User Curator + AI Curator
    ↓
本地生成 USER.md、决策卡、DECISION_RULES.md 和两份发布文本
    ↓
快照、报告、候选版本、审核与激活
```

## 5. 会话导入

每次前台任务结束后，短期记忆系统通过现有 FastAPI 接口提交完整会话。DREAM 只执行本地工作：

- 校验 `event_id`、`tenant_id`、`agent_id`、`user_id`、时间和消息结构；
- 校验 `final_response` 与最后一条 assistant 消息一致；
- 拒绝跨作用域或格式非法的记录；
- 对重复 `event_id` 幂等返回；
- 写入事件账本；
- 将事件加入对应用户的 pending 队列；
- 更新该用户的最后活动时间和估算 Token 数量。

该阶段不得调用 Agnes，也不得更新 active 画像和决策规则。

## 6. 自适应 Background Review 触发

固定“五段会话”仅用于可控的正式测试，不作为生产环境唯一条件。生产环境按用户作用域检查 pending 队列，满足任一条件时触发批量 Review：

1. 当前用户已经空闲 2 小时，并且至少存在一条 pending 会话；
2. pending 输入达到 16,000 个估算 Token；
3. pending 事件达到 20 条；
4. 最早一条 pending 会话已经等待 24 小时；
5. 管理员通过现有接口手动触发。

建议配置：

```dotenv
DREAM_REVIEW_IDLE_HOURS=2
DREAM_REVIEW_MAX_BATCH_TOKENS=16000
DREAM_REVIEW_MAX_BATCH_EVENTS=20
DREAM_REVIEW_MAX_WAIT_HOURS=24
```

“空闲”按 `tenant_id + agent_id + user_id` 判断，而不是按整个企业 Agent 判断。企业 Agent 可能全天服务不同用户，如果使用全局空闲条件，做梦可能永远无法触发。

批次超过 Token 或事件上限时按事件完成顺序切分；单个事件不得拆成半段会话。没有 pending 会话时不得创建空做梦任务。

## 7. Agnes 的唯一常规职责

一个批次的正常路径只发起一次联合语义提炼请求。输入包括：

- 当前批次内同一用户的完整会话和每个 `event_id`；
- 当前 active `USER.md`；
- 当前 active 决策规则和决策卡摘要；
- 允许输出的用户事实与 AI 决策经验结构。

Agnes 只返回提议，不获得磁盘写权限。每项输出必须标注来源 `event_id`。

用户事实提议至少包含：

- 操作类型：新增、替换或移除；
- 新事实内容；
- 被替换或移除条目的稳定 ID；
- 支持该事实的来源事件。

AI 决策经验提议至少包含：

- 合法卡片 ID；
- 标题、使用场景、决策信号；
- 决策原则、结果和边界；
- 置信度和来源事件。

本地代码在应用之前验证必填字段、非空文本、ID、证据、长度、作用域和隐私边界。无效输出只允许在同一个做梦候选内进行一次带校验反馈的修复请求；不得创建三个失败版本进行盲目重试。第二次仍无效时，本批次安全失败并保持 pending。

## 8. 确定性 Curator

普通 Curator 分为 Agent 级 AI Curator 和用户级 User Curator，均不调用外部模型。

### 8.1 AI Curator

- 每个 Agent 只运行一次，不能因多个用户同时做梦而重复运行；
- 读取 active 决策卡；
- 按稳定卡片 ID和规范化决策原则精确去重；
- 合并来源事件；
- 将完全重复或明确被替代的卡片移入可恢复的 `.archive`；
- 生成 `DECISION_RULES.md`；
- 不物理删除决策卡。

### 8.2 User Curator

- 对每个发生变化的 `user_id` 单独运行；
- 读取该用户的 `USER.md`；
- 按稳定条目 ID和规范化内容精确去重；
- 合并来源事件；
- 保留替换历史和全部证据；
- 检查画像长度、格式和用户作用域；
- 不读取其他用户的 `USER.md`。

建议默认配置：

```dotenv
DREAM_CURATOR_BACKEND=deterministic
DREAM_CURATOR_CONSOLIDATE=false
```

## 9. Curator 双触发策略

确定性 Curator 有两个触发入口。

### 9.1 做梦完成后的立即触发

每次批量 Background Review 成功应用后，立即运行对应用户的 User Curator，并为发生决策卡变化的 Agent 运行一次 AI Curator。

### 9.2 每日凌晨 3 点兜底

调度器按 `Asia/Shanghai` 每天 03:00 扫描发生变化但尚未整理的作用域：

- 决策卡发生变化：为每个 Agent 运行一次 AI Curator；
- `USER.md` 发生变化：为对应用户分别运行 User Curator；
- 没有变化：只记录检查状态，不改文件；
- 同一作用域正在做梦：等待、跳过并在本轮完成后补跑；
- 服务在 03:00 未运行：重启后检查持久化状态，有遗漏且存在变化时补跑一次。

建议配置：

```dotenv
DREAM_TIMEZONE=Asia/Shanghai
DREAM_CURATOR_DAILY_HOUR=3
```

调度状态必须记录 `last_checked_at`、`last_success_at`、处理的作用域和失败原因，避免同一天重复补跑。

## 10. 可选大模型语义 Curator

深度语义合并默认关闭。只有配置 `DREAM_CURATOR_CONSOLIDATE=true` 后才创建独立的辅助整理任务。

建议配置：

```dotenv
DREAM_CURATOR_CONSOLIDATE=false
DREAM_CURATOR_CONSOLIDATE_INTERVAL_HOURS=168
DREAM_CURATOR_CONSOLIDATE_MIN_IDLE_HOURS=2
```

启用后，只有同时满足以下条件才运行：

- 距离上次语义合并已经达到 7 天；
- 目标作用域至少空闲 2 小时；
- 当前没有普通做梦或待审核候选占用相同作用域；
- 存在足够的画像或决策卡候选内容。

该任务可以判断文字不同但语义重复的画像、复杂冲突、相似决策卡和综合规则。它必须在独立工作副本上生成候选，不能直接覆盖 active 文件。失败时只写报告并丢弃工作副本，不回滚已经成功的普通 Background Review 和确定性 Curator，也不阻止下一任务使用当前 active 版本。

## 11. 本地回写

`CHARACTER_DEFINITION.md` 和 `USER_PERSONA.md` 是从已经整理好的决策规则和用户画像派生的发布文本，不再调用 Agnes。

- Character Definition 从 `DECISION_RULES.md` 按固定模板和长度限制生成；
- User Persona 从当前用户 `USER.md` 去除内部证据注释后按固定模板生成；
- 回写前执行非空、长度、敏感信息和来源边界检查；
- 同时写入前创建快照；
- 任一文件校验失败时不生成 ready 候选。

建议新增独立配置：

```dotenv
DREAM_WRITEBACK_BACKEND=deterministic
```

## 12. 事务、锁和下一任务

- 用户画像写入使用用户级锁；
- 决策卡和 AI Curator 使用 Agent 级锁；
- 相同作用域一次只能存在一个普通做梦候选；
- pending 未达到触发条件时，下一任务可以继续使用当前 active 版本；
- 做梦开始、候选待审核或待激活时，同一用户的新任务由任务启动屏障阻止；
- 新版本激活后，下一任务获取新的上下文快照；
- 已开始的任务继续使用启动时冻结的快照，不被后台更新改变。

## 13. 超时、重试和失败恢复

建议配置：

```dotenv
DREAM_LLM_TIMEOUT_SECONDS=90
DREAM_DREAM_DEADLINE_SECONDS=300
DREAM_LLM_REPAIR_ATTEMPTS=1
```

一次批量 Agnes 请求最多允许一次结构修复，总做梦时间不超过 300 秒。达到截止时间后取消未完成步骤、恢复做梦前快照、保留 pending 事件并写入失败报告。

模型输出通过严格本地校验后保存为带输入哈希、模型、提示词版本和批次事件 ID 的阶段结果。后续本地 Curator、格式化或报告失败时，重试可以复用该阶段结果，不再次调用 Agnes；输入、模型或提示词变化时缓存自动失效。

## 14. 时间目标

| 阶段 | 目标 |
|---|---:|
| 单段或批量会话导入 | 通常小于 10 秒，最长不超过 2 分钟 |
| 一次 Agnes 批量语义提炼 | 目标不超过 180 秒 |
| 本地校验、Manager 和确定性 Curator | 目标不超过 30 秒 |
| 本地回写、快照、报告和候选版本 | 目标不超过 30 秒 |
| 整次普通做梦 | 300 秒内成功或安全失败 |

这些时间是 DREAM 的服务目标，不是外部模型的成功保证。真实 Agnes 测试需要记录每个阶段耗时和 P50、P95。

## 15. API 兼容

保留现有会话导入、手动做梦、审核、确认回写、激活、状态和任务启动接口。新增调度和批次逻辑位于服务内部；外部短期记忆项目不需要了解 Curator 或模型细节。

手动 `/v1/validation/dream` 仍可立即处理指定作用域的 pending 会话，用于测试、运维和人工恢复。生产自动触发与手动触发必须复用同一个闭环协调器。

## 16. 验证要求

自动化测试至少覆盖：

1. 导入会话不调用模型；
2. 同一用户的多条 pending 会话只产生一次批量模型请求；
3. 不同用户不会进入同一个用户画像批次；
4. 空闲、Token、事件数、最长等待和手动触发条件；
5. 无 pending 时所有定时任务均为无操作；
6. 确定性 Curator 运行时模型调用数为零；
7. 每日 03:00 调度、错过后的补跑和同日幂等；
8. AI Curator 每个 Agent 只运行一次，User Curator 按用户隔离；
9. `consolidate=false` 时不创建辅助模型任务；
10. 可选语义 Curator 失败不破坏普通做梦结果；
11. Agnes 返回空字段、非法 ID、错误来源或超时时安全失败；
12. 修复重试发生在同一个候选中，不创建连续失败版本；
13. 本地后续步骤重试复用已验证的语义阶段结果；
14. 做梦期间任务启动屏障返回 409，激活后返回最新快照；
15. 服务重启后恢复 pending、调度状态和错过的凌晨任务。

正式 30 段验证继续使用每 5 段人为制造一次任务空隙，共六个可比较周期；这只是测试编排，不改变生产自适应触发策略。

## 17. 验收标准

- 一个测试批次的正常路径只记录一次 Agnes 语义请求；首次输出结构非法时最多允许一次修复请求，总调用数不得超过两次；
- 确定性 Curator 和本地回写不产生模型请求；
- 普通做梦在 300 秒内成功或恢复到原 active 状态；
- 任意失败均不留下半激活产物；
- 不同用户画像零交叉；
- 每日 03:00 定时任务可观察、可补跑且不重复；
- 可选语义 Curator 默认关闭，开启后的失败不阻塞普通闭环；
- 原始事件、画像证据、决策卡来源、快照和发布版本均可从磁盘检查。
